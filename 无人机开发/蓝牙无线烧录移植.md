对于同一块 WHEELTEC F570 飞控，真正需要重复做的操作可以压缩为下面 6 项。BootLoader 只需预先烧录一次，不要每个工程重复烧录。

## 每个新 CLion 工程的最少操作

### 1. 在 CubeMX 中配置蓝牙串口

同一块 F570 板固定使用：

```
UART4_TX：PC10
UART4_RX：PC11
波特率：230400
模式：Asynchronous
UART4 global interrupt：Enable
FreeRTOS工程中断优先级：5
```

同时保持正确时钟：

```
HSE：8 MHz
SYSCLK：168 MHz
```

生成 CMake 工程。

### 2. 修改链接脚本

修改 `STM32F405xx_FLASH.ld`：

```
MEMORY
{
  RAM (xrw)      : ORIGIN = 0x20000000, LENGTH = 128K
  CCMRAM (xrw)   : ORIGIN = 0x10000000, LENGTH = 64K
  FLASH (rx)     : ORIGIN = 0x08010000, LENGTH = 960K
}
```

最关键的是：

```
FLASH (rx) : ORIGIN = 0x08010000, LENGTH = 960K
```

### 3. 在 CMake 中配置 VTOR

在根 `CMakeLists.txt` 的：

```
add_subdirectory(cmake/stm32cubemx)
```

后面加入：

```
target_compile_definitions(stm32cubemx INTERFACE
    USER_VECT_TAB_ADDRESS
    VECT_TAB_OFFSET=0x10000U
)
```

必须作用于 `stm32cubemx`，不要只写成：

```
target_compile_definitions(Base PRIVATE ...)
```

否则 `system_stm32f4xx.c` 可能收不到宏，程序烧录成功后会在第一次中断时跑飞。

### 4. 加入 `reset` 接收功能

最省事的方式是复制当前已经验证的：

```
Base/App/uart_callback.c
```

到新工程的 `App` 目录，然后在根 `CMakeLists.txt` 中添加：

```
target_sources(${CMAKE_PROJECT_NAME} PRIVATE
    ${CMAKE_CURRENT_SOURCE_DIR}/App/uart_callback.c
)
```

在 `main.c` 的用户变量区定义：

```
uint8_t uart1_recv;
uint8_t uart4_recv;
```

UART初始化完成后启动接收：

```
HAL_UART_Receive_IT(&huart1, &uart1_recv, 1);
HAL_UART_Receive_IT(&huart4, &uart4_recv, 1);
```

如果新工程不使用 USART1，可以精简 `uart_callback.c`，只保留 UART4相关代码。

UART4 收到小写 ASCII：

```
reset
```

后执行：

```
NVIC_SystemReset();
```

芯片就会重新进入 `0x08000000` 的 BootLoader。

### 5. 自动生成 BIN

确认工具链文件中存在：

```
set(CMAKE_OBJCOPY ${TOOLCHAIN_PREFIX}objcopy)
```

在根 `CMakeLists.txt` 末尾加入：

```
add_custom_command(TARGET ${CMAKE_PROJECT_NAME} POST_BUILD
    COMMAND ${CMAKE_OBJCOPY} -O binary
            $<TARGET_FILE:${CMAKE_PROJECT_NAME}>
            ${CMAKE_PROJECT_NAME}.bin
    COMMENT "Generating ${CMAKE_PROJECT_NAME}.bin"
)
```

如果还需要 HEX：

```
add_custom_command(TARGET ${CMAKE_PROJECT_NAME} POST_BUILD
    COMMAND ${CMAKE_OBJCOPY} -O ihex
            $<TARGET_FILE:${CMAKE_PROJECT_NAME}>
            ${CMAKE_PROJECT_NAME}.hex
    COMMAND ${CMAKE_OBJCOPY} -O binary
            $<TARGET_FILE:${CMAKE_PROJECT_NAME}>
            ${CMAKE_PROJECT_NAME}.bin
    COMMENT "Generating HEX and BIN"
)
```

### 6. 重新配置并构建

新工程第一次修改完成后执行：

```
cmake --preset Release --fresh
cmake --build --preset Release
```

生成文件通常位于：

```
build/Release/工程名.bin
```

然后在无线烧录上位机中重新选择这个文件。

## 每次烧录前的最低验证

检查向量表：

```
arm-none-eabi-objdump -h .\build\Release\工程名.elf |
  Select-String '\.isr_vector'
```

必须看到：

```
.isr_vector ... 08010000 08010000
```

再检查 `system_stm32f4xx.c` 的真实编译命令：

```
Select-String `
  -LiteralPath .\build\Release\compile_commands.json `
  -Pattern 'system_stm32f4xx.c'
```

必须同时包含：

```
-DUSER_VECT_TAB_ADDRESS
-DVECT_TAB_OFFSET=0x10000U
```

## 最推荐的工作方式

不要每次从完全空白工程重新配置。把当前已经验证成功的 `Base` 作为“无线烧录工程模板”。

以后新建程序时：

1. 复制 `Base` 工程。
2. 修改工程名。
3. 使用 CubeMX 增加需要的外设。
4. 编写新的无人机功能。
5. 构建 Release。
6. 选择新的 `.bin` 无线烧录。

这样链接地址、VTOR、UART4 reset 和 BIN 生成逻辑都能直接保留，最不容易再次踩坑。

最简记忆口诀是：

```
UART4能收reset
+ APP链接到08010000
+ VTOR指向08010000
+ CMake生成BIN
= 可以持续无线升级
```
