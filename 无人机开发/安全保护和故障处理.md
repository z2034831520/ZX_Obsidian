# 安全保护和故障处理

## 安全状态机

飞行安全不应依赖单个 `if`。建议用明确状态管理解锁、待机、飞行、降级、返航、降落和终止，并记录触发原因。

## 典型保护条件

- 电池低电压、低容量或电源异常。
- 遥控、数传或外部控制链路超时。
- 姿态、位置或高度估计失效。
- IMU 饱和、传感器掉线或数据超时。
- 电机输出异常、机体翻转或持续失控。
- 超出地理围栏、最大高度或任务范围。
- 主循环、任务或通信看门狗超时。

保护动作应按严重程度分级，例如警告、保持、返航、降落、禁止解锁和终止输出。多个故障同时出现时通常选择更安全、等级更高的动作。

## 解锁前检查

检查传感器健康、姿态方向、电池、遥控、模式、定位质量、参数完整性和电机输出状态。不满足条件时应拒绝解锁，并给出可诊断的原因。

## 测试原则

先在仿真或拆桨条件下测试低电、断遥控、断数传、传感器异常和任务卡死，再逐步进入系留或低风险实飞。必须验证“检测到故障”以及“执行了正确动作”两个环节。

## 常见问题

- 只设置超时，不定义超时后的明确动作。
- 故障后仍沿用最后一次控制量。
- 保护逻辑无法区分地面和空中状态。
- 保护动作本身未经仿真和日志验证。
- Kill、Disarm、Land 和 Return 的语义混淆。
