# 事件组与任务通知

## 事件组

事件组用一个位集合表示多个布尔事件。任务可以等待任意一位或全部位满足，并选择退出等待时是否自动清除相应位。

```c
#define WIFI_READY  (1U << 0)
#define MQTT_READY  (1U << 1)

EventBits_t bits = xEventGroupWaitBits(
    group,
    WIFI_READY | MQTT_READY,
    pdFALSE,
    pdTRUE,
    portMAX_DELAY
);
```

事件组适合“多个条件是否完成”，不适合累计同一事件发生次数，因为重复设置同一位不会增加计数。

## 任务通知

每个任务内部拥有通知状态和通知值，可用作轻量事件、位标志、二值或计数信号量。通知直接发送给目标任务，不需要单独创建内核对象，通常比队列或信号量开销更低。

常用接口包括 `xTaskNotify()`、`xTaskNotifyWait()`、`xTaskNotifyGive()` 和 `ulTaskNotifyTake()`。中断中使用对应的 `FromISR` 版本。

## 选择原则

- 单一接收任务、追求低开销：优先任务通知。
- 多个独立条件组合等待：使用事件组。
- 需要传递结构体或多条排队消息：使用队列。
- 需要多个任务竞争资源：使用信号量或互斥锁。

## 常见问题

- 多个发送者覆盖同一个任务通知值。
- 把事件位当成事件计数器。
- 清除事件位的时机错误，导致事件丢失。
- 任务通知固定绑定接收任务，不适合多接收者广播。
