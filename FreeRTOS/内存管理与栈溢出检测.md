# 内存管理与栈溢出检测

## 动态与静态分配

FreeRTOS 对象可以动态或静态创建。动态方式使用 `pvPortMalloc()` 和 `vPortFree()` 管理内核堆；静态方式由应用提供控制块和缓冲区，内存占用更可预测。

常见内存实现：

- `heap_1`：只分配、不释放，结构最简单。
- `heap_2`：可释放，但不合并相邻空闲块，容易碎片化。
- `heap_3`：封装标准库 `malloc/free`。
- `heap_4`：可释放并合并相邻空闲块，常用于一般工程。
- `heap_5`：支持多个不连续内存区域。

工程只能选择一种 `heap_x.c` 实现。

## 失败检测

动态创建任务、队列等对象后必须检查返回值。可实现 `vApplicationMallocFailedHook()` 捕获分配失败，并观察 `xPortGetFreeHeapSize()` 与 `xPortGetMinimumEverFreeHeapSize()`。

## 栈溢出检测

在 `FreeRTOSConfig.h` 中配置 `configCHECK_FOR_STACK_OVERFLOW`，并实现：

```c
void vApplicationStackOverflowHook(TaskHandle_t task, char *name)
{
    taskDISABLE_INTERRUPTS();
    for (;;) {}
}
```

`uxTaskGetStackHighWaterMark()` 可用于估算任务历史最小剩余栈空间。调试时还应检查中断栈，因为任务栈检测不一定覆盖 MSP 或异常栈。

## 常见问题

- 把任务栈深度当成字节数。
- 忽略对象创建失败。
- 频繁创建和删除不同大小对象导致碎片。
- 只增加栈而不查找大数组、递归或格式化输出等根因。
