## 简介
- **声明**是告诉编译器“有这么一个东西存在”，但**不分配内存**。
    
- **定义**不仅告诉编译器“有这个东西”，还**真正为它分配了内存空间**（有时还包括赋初始值）。
    

我们可以用一个生活中的例子来打比方：

- **声明**就像是**名片**或者**通缉令**。它告诉大家“张三，男，30岁”，让你知道有这么个人存在，长什么样，但名片本身并不是张三这个大活人。
    
- **定义**就像是**张三本人**。他实实在在地占用了物理空间，并且这个世界上只能有一个真正的张三（单一定义规则）


## 核心对比

为了更直观地理解，我们可以通过下表进行对比：

| **特性**   | **声明 (Declaration)**      | **定义 (Definition)**                          |
| -------- | ------------------------- | -------------------------------------------- |
| **核心作用** | 告诉编译器变量/函数的**名字**和**类型**。 | 为变量/函数**分配内存空间**，并可选择初始化。                    |
| **内存分配** | **不分配**内存。                | **分配**具体的内存。                                 |
| **出现次数** | 在整个项目中可以被声明**无数次**。       | 在整个项目中**只能被定义一次**（One Definition Rule, ODR）。 |
| **主要目的** | 让编译器认识这个符号，通过语法检查。        | 让链接器找到这个符号的实际物理地址。                           |


## 作用
将声明和定义分开，是多文件编程（模块化）的基础。

当你的项目变得很大，有几十个 `.c` 文件时，你不可能把所有的代码都写在一个文件里。你需要把代码拆分。

- **头文件（`.h`）放声明**：它就像是菜单。其他文件只要包含了这个头文件，就知道了有哪些函数和变量可以使用，编译器就不会报错。
    
- **源文件（`.c`）放定义**：它就像是后厨。真正的逻辑代码和内存分配都在这里，且只存在一份。
    

当程序编译时，编译器只看声明（菜单）来检查语法；而在最后一步“链接（Linking）”时，链接器会把所有的引用指向那个唯一存在的定义（后厨）。如果在链接时找不到定义，或者找到了多个同名的定义，程序就会报错。
