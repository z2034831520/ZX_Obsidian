## 简介
状态机是一种逻辑模型，他认为一个系统在任一时刻，只能处于有限个状态中的某一个，当某个事件发生时，系统会自动执行某个动作，并从当前状态转换到另一个状态。

例如一台全自动洗衣机：它有“注水”、“洗涤”、“漂洗”、“脱水”几个状态。在“注水”状态下，洗衣机的大脑并不会进入“死循环”傻等，它依然可以随时响应你按下“暂停”按钮（事件）。它只是处于“注水”这个状态，不断检查水位传感器是否触发。

## 组成
状态机主要由四个核心部分组成

- 状态：当前系统处于什么阶段（例如：等待中，正常运行）
- 事件：触发状态改变的条件（例如：按键被按下）
- 动作：状态跳转时执行的操作（例如：点亮LED灯）
- 转移：从一个状态切换到下一个状态的过程

## 作用
在裸机开发中我们离不开状态机，否则我们就无法进行流畅的状态切换，假设我们现在想要实现让`LED`亮100ms然后灭900ms，如果不用状态机且采用阻塞式写法，代码如下：

```c
void Task_LED(void) {
    LED_ON();
    delay_ms(100);  // 灾难：CPU在这里空转
    LED_OFF();
    delay_ms(900);  // 灾难：CPU再次空转
}
```

如果我们使用状态机和非阻塞式写法，代码如下：
```c
// 1. 定义状态枚举
typedef enum {
    STATE_LED_ON,
    STATE_LED_OFF
} LedState_t;

void Task_LED(void) {
    // 静态变量，保证退出函数后值不丢失
    static LedState_t current_state = STATE_LED_OFF; 
    static uint16_t time_counter = 0; 

    // 每进一次函数，时间计数器加 10ms (因为调度器每10ms调一次)
    time_counter += 10; 

    // 2. 状态机本体
    switch (current_state) {
        case STATE_LED_OFF:
            // 等待 900ms
            if (time_counter >= 900) {
                LED_ON();                    // 动作
                time_counter = 0;            // 清零计时器
                current_state = STATE_LED_ON; // 状态转移
            }
            break;

        case STATE_LED_ON:
            // 等待 100ms
            if (time_counter >= 100) {
                LED_OFF();                    // 动作
                time_counter = 0;             // 清零计时器
                current_state = STATE_LED_OFF; // 状态转移
            }
            break;
    }
    // 函数执行只需几微秒，瞬间 return，将 CPU 交还给调度器
}
```

## 优势
当前单片机的优势如下
- 代码逻辑性强：当我们需要实现复杂的交互逻辑时，我们通过状态机就可以避免使用`if-else`
- 调试难度低：如果系统出错了，只需要打印当前的状态机总变量，然后就能立刻知道系统卡在了哪个阶段
- 性能强：所有的任务瞬进瞬出且由于事件片轮转的特性，每个功能中都极少使用延时等功能，系统的响应速度较快
