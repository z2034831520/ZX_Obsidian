# STM32G474 与 W5500 步进电机项目：三分钟通信架构介绍

> 面向零基础同学的口头讲稿，约三分钟。可配合已有的“OK PASS”“OK REJECT”截图讲解；不依赖现场联网演示。以下内容根据当前项目源码整理，本次没有进行硬件复测。

## 开场｜约 20 秒

先看结果：电脑发送数字 1，表示目标合格，开发板亮绿灯，不会因此新启动步进电机；发送数字 0，表示目标不合格，开发板亮红灯，并尝试启动剔除运动。我们要解释的，就是这一条信息怎样从电脑到达单片机，再变成灯光和电机动作。

## 网口主路径｜约 80 秒

网口通信时，电脑上的程序是 TCP 客户端，主动连接开发板的固定地址 192.168.1.200、端口 5000。网线先接到路由器的 LAN 网络，再到开发板上的 W5500 模块。这里的路由器主要帮两端建立局域网连接；通信不要求路由器接入互联网。

W5500 可以理解成专门处理网络通信的芯片：它处理以太网、IP 和 TCP，把电脑送来的内容放在接收缓冲区。STM32G474 本身不是直接从网线读取文字，而是通过 SPI1 与 W5500 交换数据，再从中取出收到的字节。程序把这些字节拼成一条指令，交给统一的解析逻辑处理。

TCP 在这里负责可靠地传送字节、维持连接；它不规定“0”或“1”代表什么。本项目也没有使用 HTTP 网页协议，而是在普通 TCP 连接里传自定义的文本指令。

## 串口并列路径｜约 35 秒

除了网口，项目还保留 USART1 串口入口。上位机通过合适的串口连接把数据送到单片机后，串口程序也会调用同一套指令解析逻辑。因此，网口和串口是两条并列入口，后面的判断与控制规则相同。它们可以分别使用，但当前程序没有“网口断了就自动切换串口”的故障切换功能。

## 指令与回复｜约 35 秒

网口这边发送的是 ASCII 文本，换行符表示一条指令结束，例如发送 1 加换行、0 加换行，或者 STATUS 加换行。串口对单个 0 或 1 还支持直接处理，不必等换行。收到 1，程序显示绿灯并回复 OK PASS；收到 0，显示红灯并尝试下达剔除命令，命令被接受时回复 OK REJECT。要注意：OK REJECT 只表示剔除命令被接受，不等于机械动作已经完成；收到 1 也不会打断正在进行的剔除动作。

## 收束｜约 10 秒

一句话总结：TCP 负责电脑与 W5500 的网络连接，SPI1 负责 W5500 与 STM32 的芯片间传输，USART1 是另一条入口，0、1、STATUS 等文本是我们自己定义的指令。当前断线重连体验还有待优化。

## 路径速览（不必逐字朗读）

~~~text
电脑 TCP 客户端 → 路由器 LAN → W5500 → SPI1 ┐
                                            ├→ STM32 共同指令解析 → LED / 步进电机
上位机串口连接 ───────────────→ USART1 ┘
~~~

两条入口并列，不自动故障切换。网口指令以换行结束；串口单个 0 / 1 可直接处理。回复沿原通信通道返回。
