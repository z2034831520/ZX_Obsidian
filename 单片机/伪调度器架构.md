## 简介
伪调度器架构是裸机开发中最优秀的架构之一，广泛应用于各类传感器的读取

## 与[时间片轮转](时间片轮转.md)的区别
- **时间片轮转：** 强调的是“你能运行多长时间”。系统规定每个任务每次最多只能运行 $X$ 毫秒（时间片）。时间一到，无论任务有没有干完活，都必须交出 CPU。
    
- **伪调度：** 结构体中的 `rate_ms` 定义的是任务的**执行周期**（“你多久需要被执行一次”），而不是执行时长。当条件 `(now_time - last_run) >= rate_ms` 满足时，任务函数 `task_func()` 被调用。**一旦任务开始运行，调度器就失去了控制权**。任务想运行多久就运行多久，直到它遇到 `return` 结束自己

## 实现方式

### 1. 核心数据结构设计

首先，我们需要定义任务的“身份证”——任务控制块。在这里，我们不使用繁琐的倒计时变量，而是记录任务的“执行周期”**和**“上次执行时间”


```
#include <stdint.h>
#include <stddef.h>

// 定义任务函数指针
typedef void (*TaskFunc_t)(void);

// 任务控制块 (Task Control Block)
typedef struct {
    TaskFunc_t task_func;   // 任务具体执行的函数
    uint32_t   period_ms;   // 任务执行周期 (单位: 毫秒)
    uint32_t   last_run;    // 记录上次执行的系统时间戳
    uint8_t    is_enable;   // 任务使能标志 (1: 运行, 0: 暂停)
} Task_t;
```

### 2. 编写非阻塞任务并建立任务表

将你需要的所有任务按周期注册到一个静态数组中。**所有的任务内部绝不能有死循环或 `delay_ms` 等阻塞操作。**


```
// 外部声明任务函数 (实际开发中通常包含在各自的头文件里)
extern void Task_KeyScan(void);
extern void Task_LED_Blink(void);
extern void Task_SensorRead(void);

// 任务注册表 (可根据需求随时增减)
static Task_t task_list[] = {
    // 任务函数           执行周期(ms)  上次执行时间(默认0)  使能状态
    {Task_KeyScan,       10,          0,                 1}, // 10ms消抖扫描
    {Task_LED_Blink,     500,         0,                 1}, // 500ms闪烁
    {Task_SensorRead,    1000,        0,                 1}  // 1s读取一次传感器
};

// 获取系统中总共有多少个任务
#define TASK_NUM (sizeof(task_list) / sizeof(task_list[0]))
```

### 3. 构建系统心跳 

调度器需要一个精准的时间基准。我们通常配置硬件定时器（如 Cortex-M 系列的 SysTick）产生 1ms 的中断。 在中断服务函数里，我们**只做一件事：让全局时间戳加一**。不在中断里执行任何业务逻辑！

C

```
// 全局系统运行时间戳
static volatile uint32_t g_sys_tick_ms = 0;

// 定时器中断服务函数 (硬件每 1ms 自动触发一次)
void SysTick_Handler(void) {
    g_sys_tick_ms++;
}

// 提供一个获取当前系统时间的接口
uint32_t GetSysTick(void) {
    return g_sys_tick_ms;
}
```

### 4. 编写调度器核心引擎

这是伪调度器的心脏。在 `main()` 函数的死循环中，引擎会不断遍历任务表，检查每个任务的时间是否达标。

C

```
void Scheduler_Run(void) {
    uint32_t current_time;

    while (1) {
        // 获取当前时间戳
        current_time = GetSysTick();

        // 遍历所有任务
        for (uint8_t i = 0; i < TASK_NUM; i++) {
            
            // 如果任务被禁用，则跳过
            if (task_list[i].is_enable == 0) {
                continue; 
            }

            // 【核心逻辑】检查时间是否到达
            // 使用减法 (current_time - last_run) 可以完美解决 32位时间戳溢出(溢出归零)的问题
            if ((uint32_t)(current_time - task_list[i].last_run) >= task_list[i].period_ms) {
                
                // 1. 更新上次执行时间
                task_list[i].last_run = current_time;
                
                // 2. 执行任务
                if (task_list[i].task_func != NULL) {
                    task_list[i].task_func();
                }
            }
        }
    }
}
```

### 5. 在 Main 函数中启动

最后，将各部分组合起来，你的裸机系统就具备了强大的并发处理能力：

C

```
int main(void) {
    // 1. 硬件初始化 (时钟、GPIO、串口等)
    BSP_Init();
    
    // 2. 配置 SysTick 定时器，使其每 1ms 产生一次中断
    SysTick_Config(SystemCoreClock / 1000); 

    // 3. 启动调度器引擎 (此函数内部为死循环，永不返回)
    Scheduler_Run();

    return 0;
}
```
## 优势
- **极度轻量：** 代码只有寥寥几十行，不消耗额外的 RAM。
    
- **避免了中断拥堵：** 时间戳的获取（`GetSysRunTime()`）通常在 SysTick 中断里只做 `time++`，而繁重的任务逻辑都在主循环中执行，非常健康。
    
- **时间溢出安全：** 使用 `(now_time - last_run) >= rate_ms` 这种减法计算，完美利用了无符号整数（`uint32_t`）的回绕特性，即使系统连续运行 49 天导致 `now_time` 溢出归零，时间计算依然是准确的。
