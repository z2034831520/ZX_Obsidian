# 多容器应用的服务发现

同一用户自定义网络或 Compose 项目中的服务可通过 DNS 名称互相发现。客户端应连接服务名和容器端口：

```text
postgresql://db:5432/app
redis://cache:6379
```

不要在容器内用 `localhost` 访问其他服务，也不要依赖动态容器 IP。宿主机发布端口主要用于从网络外部访问容器，不是容器间通信的首选路径。

服务发现只解决“地址在哪里”，不保证目标服务已经就绪。启动阶段应使用健康检查、连接重试、指数退避和合理超时。应用运行期间也必须能处理依赖重启和 DNS/IP 更新。

## 设计原则

- 按信任边界划分多个网络。
- 数据库通常不需要发布到宿主公网。
- 服务名保持稳定，容器实例可以替换。
- 客户端设置连接、读取和总超时。
- 不把启动顺序当作健康状态。
- 记录请求链路和依赖错误，便于排查。
