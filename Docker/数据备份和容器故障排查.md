# 数据备份和容器故障排查

## 数据备份

先识别数据位置：命名卷、绑定挂载、外部数据库或对象存储。数据库备份优先使用数据库自身的一致性备份工具；直接复制正在写入的数据目录可能得到不可恢复的快照。

备份必须包含：

- 数据和必要配置。
- 镜像版本或部署清单。
- 加密密钥的受控恢复方案。
- 恢复步骤和恢复验证。
- 保留周期与异地副本。

没有执行过恢复演练的备份不能算已验证备份。

## 故障排查顺序

```bash
docker ps -a
docker inspect container
docker logs --tail 200 container
docker stats
docker network inspect network
docker volume inspect volume
```

1. 检查容器状态、退出码和重启次数。
2. 查看应用日志和健康检查输出。
3. 验证环境变量、挂载、权限和磁盘空间。
4. 检查网络、DNS、监听地址和依赖服务。
5. 检查 OOM、资源限制和宿主内核日志。
6. 使用相同镜像和配置构造最小复现。

不要在故障容器中手工修改后直接当作永久修复；应把修复写回 Dockerfile、Compose 文件或部署配置。
