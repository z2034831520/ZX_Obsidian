# 日志、资源限制和健康检查

应用应把普通日志写到 stdout，把错误日志写到 stderr，由 Docker 日志驱动收集。

```bash
docker logs --tail 200 -f app
docker stats
docker inspect app
```

日志必须设置轮转或集中采集，否则宿主磁盘可能被占满。

## 资源限制

可配置 CPU、内存、进程数等限制，避免单个容器拖垮宿主机。内存不足时容器可能被 OOM Kill；应结合退出码、宿主内核日志和 `docker inspect` 判断。限制值需要基于真实负载和峰值测试设置。

## 健康检查

```dockerfile
HEALTHCHECK --interval=30s --timeout=3s --retries=3 \
  CMD curl -fsS http://localhost:8080/health || exit 1
```

健康检查回答“应用是否能提供服务”，而不仅是进程是否存在。检查应快速、稳定、无副作用，并覆盖关键依赖的合理范围。容器变为 `unhealthy` 不等于 Docker 一定会自动重启，具体恢复行为取决于编排系统。
