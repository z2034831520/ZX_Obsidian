# 工作空间、功能包与依赖关系

## 工作空间结构

典型 ROS 2 工作空间：

```text
ros2_ws/
├── src/       # 源码包
├── build/     # 构建中间文件
├── install/   # 安装结果和环境脚本
└── log/       # 构建日志
```

只应手工维护 `src` 中的源码；其余目录通常由 colcon 生成。

## 功能包

功能包是 ROS 2 代码、接口和资源的基本分发单元。C++ 包常使用 `ament_cmake`，Python 包常使用 `ament_python`。每个包都有 `package.xml` 声明名称、版本、许可证和依赖。

```bash
ros2 pkg create --build-type ament_cmake demo_cpp --dependencies rclcpp std_msgs
ros2 pkg create --build-type ament_python demo_py --dependencies rclpy std_msgs
```

## 依赖关系

依赖应同时体现在 `package.xml` 和构建配置中。C++ 包还需在 `CMakeLists.txt` 中查找和链接依赖；Python 包需在 `setup.py` 或相关配置中安装模块和资源。

```bash
cd ros2_ws
rosdep install --from-paths src --ignore-src -r -y
colcon build --symlink-install
source install/setup.bash
```

新的终端必须注入 ROS 2 基础环境和工作空间环境。多个工作空间叠加时，后注入的 overlay 可以覆盖 underlay 中同名资源。

## 常见问题

- 在工作空间根目录而不是 `src` 创建包。
- 忘记声明依赖，导致只在本机偶然可用。
- 构建后没有 source 对应的 setup 文件。
- 同名包来自多个工作空间，实际加载版本与预期不同。
