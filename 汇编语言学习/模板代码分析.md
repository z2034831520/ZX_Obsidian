## 模板代码分析
当我们学习一门新的编程语言时最开始往往都是以该语言的起手式代码开始的，例如我们学习C语言时对应的起手式代码就是：
```c
#include <stdio.h>

int main(void)
{
    printf("Hello, World!\n");
    return 0;
}
```
`Python`的起手式代码就是：
```python
def main() -> None:
    print("Hello, World!")


if __name__ == "__main__":
    main()
```
起手式代码是后续所有高阶代码的基础，学习他们能够让我们快速认识一门新的语言，帮助我们建立自信，下面展示的就是汇编语言的起手式代码
```nasm
; 模板代码

DATA SEGMENT

    RESULT DW 0

DATA ENDS
  

STACK SEGMENT STACK

    DB 128 DUP(?)

STACK ENDS

CODE SEGMENT

    ASSUME CS:CODE, DS:DATA, SS:STACK

START:

    MOV AX, DATA
    MOV DS, AX

  
    ; TODO: put your instructions here.

    ; Keep the result in AX or RESULT when debugging.


    MOV AX, 4C00H

    INT 21H

CODE ENDS

END START
```
乍一看发现汇编语言的起手式代码比我们之前学过的高级语言的起手式代码都要复杂，但是实际上它们都是有着固定的格式的，汇编语言代码同样可以进行拆分

### 数据段
数据段的代码如下：
```nasm
DATA SEGMENT
	RESULT DW 0
DATA ENDS
```
#### 作用
数据段代码用于存放程序运行期间需要用到的全局变量
### 代码解析
`DATA SEGMENT`和`DATA ENDS`往往是成对出现的，标志着数据段的开始和结束，`DATA`是段名，可以自定义，但是通常约定俗成叫`DATA`

在代码段中我们定义了一个名为`Result`的变量，`DW`是`Define Word`的缩写，作用是定义一个字，并将其初始值设置为0，我们后续程序计算出的结果通常会被保存在这个变量中
### 栈段
栈段的代码如下：
```nasm
STACK SEGMENT STACK
    DB 128 DUP(?)
STACK ENDS
```

#### 作用
栈段中栈主要用于临时保存数据、保存函数调用的返回地址以及现场保护
#### 代码解析
当前在栈段中我们创建了一个128字节的连续空间，`DUP(?)`表示里面存放的数据是未知的（不需要初始化）。这相当于给程序预留了128字节的栈空间
### 代码段
代码段的代码如下：
```nasm
CODE SEGMENT
    ASSUME CS:CODE, DS:DATA, SS:STACK
```
#### 作用
代码段是执行所有指令的地方

#### 代码解析
在该部分代码中我们使用了`ASSUME`指令，该指令是一条伪指令，它的作用是建立段寄存器与我们定义的段之间的映射关系
它告诉编译器：把`CS`（代码段寄存器）指向`CODE`段，`DS`（数据段寄存器）指向`DATA`段，`SS`（堆栈段寄存器）指向`STACK`段，没有这部分代码，编译器在翻译变量地址时就会迷失方向
### 程序入口和初始化
该部分的代码如下：
```nasm
START:
    MOV AX, DATA
    MOV DS, AX
```
#### 作用
设定程序的起点，并完成数据段的物理绑定

#### 代码分析
- `START`是一个标号，代表程序的入口点（与最后的`END START`呼应）
- 虽然前面写了`ASSUME`，但这只是给**编译器**看的。在程序真正在CPU上跑起来时，你必须手动把数据段 `DATA` 的物理地址基址装入`DS`寄存器。因为`8086`架构不允许直接把段地址传给`DS`，所以必须借用通用寄存器`AX`作为中转（`DATA`->`AX`->`DS`）
### 核心代码逻辑
该部分的代码并没有编写，只有两行注释，注释的内容如下：
```nasm
; TODO: put your instructions here.
    ; Keep the result in AX or RESULT when debugging.
```
#### 作用
这是用户逻辑代码的所在地，后续所有的高阶逻辑，如加减乘除、循环、条件判断都会写在这里，执行完对应的代码逻辑之后，会将计算的结果保存在寄存器`AX`

### 安全退出
该部分的代码如下：
```nasm
MOV AX, 4C00H
    INT 21H
CODE ENDS
END START
```

#### 作用
将控制权交回系统

#### 代码分析
- `MOV AX, 4C00H`和`INT 21H`是`DOS`系统的标准中断调用。`INT 21H`是 `DOS`的核心服务，当`AH = 4CH`（包含在`4C00H`的高八位中）时，代表的指令是“终止程序并退出”。如果没有这两句，程序执行完你的逻辑后会继续往下跑，执行未知的内存垃圾，导致崩溃死机。
- `CODE ENDS`标志着代码段的结束
- `END START`告诉编译器：整个源代码到此结束，并且程序的入口标号是`START`

## 寄存器介绍
看完了上面的模板代码介绍你可能还是会感觉一头雾水，如果想要理解汇编代码的执行流程，就需要了解一些计算机的组成原理，汇编语言是最接近底层的语言，它的代码逻辑与底层的计算机构造是紧密相连的。接下来让我们了解一下代码中涉及到的寄存器的作用是什么，这样能够帮助你更好的理解模板程序

首先我们需要知道的是CPU是程序的执行者，每次当我们想要运行一个程序时，系统都会将对应的程序从硬盘加载到内存中，内存中存放了CPU需要执行的程序，程序执行过程中会涉及到很多变量和函数。CPU执行指令需要去调用对应的变量和函数时都会到内存中去寻找对应的数据，但是在这里有一个内存墙现象，即在计算机系统中，CPU的计算速度与内存的数据传输速度之间不断扩大的巨大鸿沟。简单来说：CPU运行的太快，但是内存的访问速度又太慢，这就导致CPU大部分时间都在等待数据，这就导致CPU的性能被浪费了。为了解决这一问题，工程师门想了很多办法，寄存器就是解决方案之一，寄存器位于`CPU`内部，访问速度极快，在程序运行时会将对应的变量加载到寄存器中来提高程序的运行速度，这也是我们在程序中需要访问寄存器的原因
