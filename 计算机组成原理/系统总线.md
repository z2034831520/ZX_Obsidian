## 三大总线
| 总线     | 传输内容      | 方向   |
| ------ | --------- | ---- |
| 数据总线DB | 数据        | 双向   |
| 地址总线AB | 访问哪个单元的地址 | 单向   |
| 控制总线CB | 控制信号、状态信号 | 有进有出 |
	常见考点：地址总线位数决定可寻址空间，n根地址线->$2^n$个单元，例如32位总线的可寻址空间为2的32次方，为4GB
## 总线仲裁
### 意义
总线是共享资源，同一时刻只能由一个设备占用；多个设备争用的时候需要一个裁判来决定使用的先后顺序和优先级

### 总线仲裁方式
总线仲裁主要有三种方式——本质的区别是“请求/响应信号线应该怎么连接”

| 方式      | 连线特点                   | 优先级             | 优点                   | 缺点                                    |
| ------- | ---------------------- | --------------- | -------------------- | ------------------------------------- |
| 链式查询    | 响应线串成一条链，逐个串行传         | 离控制器越近优先级越高（固定） | 设备之间的连线最少、扩充新设备的难度最低 | 优先级是固定的，靠后的设备容易**饿死**，对故障敏感度高，响应速度也较慢 |
| 计数器定时查询 | 控制器用计数值（设备地址）轮询广播      | 计数起点可以更改（灵活）    | 优先级可变、是比较折中的做法       | 需要额外的地址线、轮询有延迟                        |
| 独立请求    | 每个设备一对专线直连。控制器内排队判断优先级 | 排队电路任意配置（灵活度最高） | 响应最快、最灵活             | 线最多、结构最复杂                             |

## 总线结构
### 单总线结构
#### 工作原理
所有的计算机部件都挂载在同一条总线上，任何时刻总线上只能允许一对设备进行通信

#### 优点
结构简单，成本低、想要添加新的外设只需要直接挂在到这组总线上即可

#### 缺点
因为只有一条信息传输通路，因此当I/O设备与内存传输大量数据时，CPU就无法访问内存，只能被迫等待，这会产生严重的瓶颈效应
### 双总线结构
#### 工作原理
为了解决单总线架构中CPU与I/O设备争用总线的问题，双总线架构中构建了两条总线，分别是内存总线和I/O总线，内存总线主要用于CPU与主存之间的高速数据交换，I/O总线主要用于CPU与各个外设之间的数据交换

#### 优点
分离了高速设备与低速设备，CPU访问内存的速度不会再被速度较慢的I/O拖累，且I/O设备可以通过DMA机制直接与内存交换数据，解放了CPU
