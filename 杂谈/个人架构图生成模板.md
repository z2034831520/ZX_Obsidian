> [!summary] 使用目标
> 这是跨任务长期使用的深色技术架构图模板。每次生成架构图时，先读取本笔记，再把下方参考图作为**仅风格参考**加载；图中的 FreeRTOS 内容不能被复制到其他主题。

## 一、固定视觉规范

| 项目 | 固定规则 |
|---|---|
| 画幅 | 16:9 横图 |
| 背景 | 深蓝炭灰 `#151C23`，允许极弱明暗变化，禁止纯黑 |
| 主节点 | 深板岩灰 `#2A3540` |
| 次节点 | 板岩灰 `#35424D` |
| 强调色 | 低饱和雾蓝 `#6F8FA3`，只用于关键节点或主路径 |
| 连接线 | 蓝灰 `#8297A5`；次要关系使用同色虚线 |
| 主文字 | 暖浅灰 `#D7DCE2` |
| 次文字 | 柔灰 `#AEB8C2` |
| 材质 | 哑光、低反射、轻微立体、柔和浅阴影 |
| 字体 | 干净的现代无衬线字体，字重中等，不使用装饰字体 |
| 整体气质 | 理性、安静、克制、清晰、适合长期阅读 |

## 二、几何与布局规则

- 所有同类节点必须使用相同宽度、高度、圆角和厚度。
- 圆形调度器、汇聚点或状态点必须为正圆，同级圆点尺寸一致。
- 横向相邻节点至少保留约一个节点宽度；纵向至少保留约 0.6 个节点高度。
- 所有元素完整位于画布内，不得贴边、裁切、重叠或近距离相切。
- 默认采用左到右的信息流；层级图采用从上到下的层级。
- 主路径使用实线箭头，状态返回、事件唤醒或次要关系使用虚线箭头。
- 连接线优先走平滑直线或单次弯曲，禁止无意义交叉和过度绕行。
- 用位置、间距和雾蓝强调建立层级，不依赖发光、渐变或复杂纹理。
- 标题与图形之间必须保留清晰间隔，画面四周保持统一安全边距。

## 三、文字规则

- 技术图允许少量必要文字，标签必须由用户或可靠资料明确提供。
- 默认使用简短英文技术标签；用户提供中文标签时按原文生成。
- 所有必须文字在提示词中逐项列出并要求逐字渲染。
- 禁止模型自行补充说明、随机字符、版本号、Logo、水印或装饰性文字。
- 图片生成后必须检查拼写；有错误时只修改文字，不重做结构。


## 七、跨任务调用口令

在新的 Codex 任务中直接发送：

```text
按照 Obsidian 中的《个人架构图生成模板》生成。

主题：
图的类型：
事实来源：
节点：
节点之间的关系：
必须出现的文字：
重点强调：
```

执行时必须：

1. 通过 Obsidian 接口读取本模板。
2. 读取指定事实来源，先确认技术结构。
3. 加载本笔记中的参考图，明确标记为“仅风格参考”。
4. 生成一张候选图并检查结构、标签、间距和箭头。
5. 后续每轮只调整一个维度，避免整体风格漂移。

## 八、验收清单

- [ ] 技术关系与事实来源一致
- [ ] 所有必须标签拼写准确且没有额外文字
- [ ] 同类节点大小、圆角和间距一致
- [ ] 主路径明确，箭头方向无歧义
- [ ] 没有重叠、裁切和不必要的连接线交叉
- [ ] 深色背景、板岩灰节点和雾蓝强调色保持稳定
- [ ] 没有霓虹、玻璃、镀铬、赛博朋克或廉价科技感
- [ ] 与参考图属于同一视觉系列，但没有复制其具体内容

## 九、版本管理

- 当前稳定版本：`zhou-dark-architecture-v1`
- 调整颜色、节点形状或字体规范时提升版本号，并保留旧参考图。
- 单个主题的内容变化不提升模板版本。
- 新参考图使用 `architecture-style-reference-v2.png` 等递增文件名，禁止覆盖旧文件。
