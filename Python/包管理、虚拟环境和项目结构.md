# 包管理、虚拟环境和项目结构

## 虚拟环境

每个项目使用独立环境可避免依赖版本互相污染。

```powershell
python -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install --upgrade pip
```

执行安装时优先使用 `python -m pip`，可确保 pip 属于当前解释器。用 `python -c "import sys; print(sys.executable)"` 检查真实环境。

## 依赖管理

应用项目应记录直接依赖及必要版本范围。可使用 `requirements.txt`，现代项目也可在 `pyproject.toml` 中声明元数据和构建配置。不要把本机完整环境无差别复制成项目依赖。

## 推荐结构

```text
project/
├── pyproject.toml
├── README.md
├── src/
│   └── package_name/
│       ├── __init__.py
│       └── main.py
├── tests/
└── .venv/
```

`src` 布局可以减少在仓库根目录误导入源码的情况。虚拟环境、缓存、构建产物和密钥不应提交到 Git。

## 包与模块

一个 `.py` 文件是模块，包含多个模块的可导入目录是包。包内优先使用清晰的绝对导入或受控的相对导入，避免运行时修改 `sys.path`。

## 常见问题

- VS Code、终端和 Jupyter 使用了不同解释器。
- 使用系统级 pip 安装项目依赖。
- 项目名称与第三方包同名，导致导入遮蔽。
- 缺少锁定或版本记录，环境无法复现。
